完成模型

倒立振子モデルとは (Wikipediaより)

TOPへもどる

  • 倒立振子(inverted pendulum)とは、支点よりも重心が高い位置にある振り子をいう
  • 支点を台車に載せて実装する、台車駆動型倒立振子がよく知られている。ほとんどの応用例において振り子はある回転軸まわりにのみ運動するよう固定されており、自由度は1に制限されている。
  • 振り子は吊り下げられた状態が安定であり、したがって倒立振子は本質的に不安定であるので，倒立状態を保つためには常に能動的に制御する必要がある。このためには支軸に直接トルクを加えたり、支点を水平方向もしくは鉛直方向に移動させることにより振り子の錘の回転速度を変化させたりしてフィードバック系を構築する。支点を動かす型の倒立振子の一番簡単な例は、箒を手の上に立たせる系である。
  • 倒立振子は動力学と制御論における古典的な問題であり、制御戦略の試験用ベンチマークとして用いられる。

PID制御とは

TOPへもどる

  • 倒立の調整前にPID制御について知ろう
  • 参考資料：PID制御とは？メカニズムと役割をわかりやすく解説

オンオフ制御

  • 最も単純な調節動作に、オンオフ動作がある。例えば、バイメタル式の電気こたつ、焼肉等に使う鉄板に採用されている。これらのオンオフ動作では、目標温度まで100%の出力で上昇したあとに設定温度を超えると0%になって、温度が下がることで温度調整を行う。しかし、目標温度から戻りすぎや行き過ぎ(オーバーシュート)が発生しやすく、波を打つような制御結果になってしまい、理想的な温度調整にはいたらない。
  • オンオフ制御は、構造が簡単なため安価に構成できる点はメリットだが、上記のような問題がある。

PID制御

  • PID制御とは、温度制御などに用いられる制御方式のことである。目標とする値を設定したあとセンサーで現在の値を読み取って、目標値に近づけようと自動で調整する。PID制御によってオンオフ動作の欠点を解決することができる
  • PIDとは、以下の動作の頭文字を取っている。

    • ・P動作：Proportional (比例)

    ・I動作：Integral (積分)

    ・P動作：Derivative (微分)

  • PID制御は、以下の制御式(計算式)またはブロック線図によって表される。

PID制御の流れ

  • P動作とは、現在値と設定値の偏差(目標との差)に比例した操作量を比例帯内で働かす動作のこと．オンオフ動作のオーバーシュート(行き過ぎ)やアンダーシュート(戻りすぎ)といった問題を解消することができる。差が大きいほど強く働き、初期の修正を行う。
  • I動作は、P動作と組み合わせてPI動作として用いられます。P動作で生じたオフセット(偏差)を累積させて、その累積値に比例させた量を操作量に加えることで、誤差を補正することが可能となる。過去の偏差を累積し、比例制御だけでは残ってしまう小さな差(オフセット)を解消する。
  • D動作は、外乱の影響などによる急激な変化に反応して出力を修正する。今回の誤差が前回の誤差よりも大きい場合に操作量を変化させることで、急な変動にも対応することができる。 偏差の変化スピードに比例して操作量を調整し，外乱などによる急激な変化に対応し、素早く安定させる。

制御パラメータの調整

TOPへもどる

  • いよいよ「倒立」させて行く。
  • 倒立振子を「安定に」倒立させるためには，振子の傾き等に対して，適切にフィードバックする制御することが必要である。
  • もちろん，振子の傾きに対して，それを復元するに十分な「トルク」を発生させることが必要だが，今回製作したモデルの重さ，大きさ(高さ)，また，使用したモータ，ギア比，電池では十分なはずである。
  • もちろん、長時間動かして電池が消耗した場合はトルクがでなくなるので充電された電池と交換が必要である。1時間程度頻繁に動かすと電池の消耗が目立つようになる。
  • また，ギアには潤滑油を塗り，摩耗を防ぐ．さらに，ブラシ式モータではブラシ部の摩耗も起きる．その辺りには十分気を付けなければならない．
  • そこで，ここでは，スケッチ内の各種パラメータを調整し，安定に倒立させていく．

調整の基本方針

  • 根気強く

    • 調整の流れ

  • を繰り返す。
  • 動作の確認のポイントは倒れ方．突然倒れる，揺れがだんだん大きくなり倒れる，一方向に傾きそのまま倒れる，倒れはしないが一方向に動いていく，揺れが大きい，など
  • 揺れの様子からどのパラメータを変更すれば良いか推定し(難しいが．．)，調整後また動かしてみる．
  • 基本的に，一回に一つのパラメータを変更するのが「コツ」。

制御パラメータ

  • 制御するパラメータは、スケッチ内の下記パラメータである。値はおおよその値を適当に入れている。

      • // 制御パラメータの初期値

    1. float Kp = 5000.; // Pゲイン
    2. float Ki = 5.0; // Iゲイン
    3. float Kd = 25.0; // Dゲイン
    4. float Ks = 50.0; // Pゲインの2乗
    5. float Kvel = 0.0; // 速度FBゲイン0.1
    6. float Kpos = 0.8; // 位置FBゲイン0.5
    7. float Kpfilt = 0.05; // Pのfilter係数
    8. float Kdfilt = 0.95; // Dのfilter係数
    9. float Kposdec = 0.999; // posの減衰係数
    10. float Kpwma = 1.05; // モータAのPWMの係数、基準は1.0 右側
    11. float Kpwmb = 0.95; // モータBのPWMの係数、基準は1.0 左側
    12. float Kt = 0.7; // 電池の消耗を考慮する係数、最初は~0.7、最後は~1.0、pwmの係数
    13. float target = -6.7; // 目標値 モジュールが横置きなら0前後、縦置きなら90前後

まずは

  • 最初に調整するのは，調整項目の(13) float_target、「目標値」(バランスが取れる角度)である．
  • スケッチ書き込み時は，模型は倒れている状態である．手で倒立させて，モータがほぼ止まっている角度で手を離し，その直後の動きを確認する．
  • 模型がすぐに一方向にのみ倒れるようであれば、目標値がずれている。target値を調整して、倒れる方向が偏らないような値にする。後で度々微調が必要となるが、まずは粗く調整する。
  • 模型の重さがタイヤに対して対称なら0度近くになるが、電池やモータ等の配置が非対称なので、少し傾いた状態でバランスするはずである。上記の例では-6.7度傾いている．

次は

  • 次に優先して調整するのは、(1)～(3)のPID制御パラメータである。
  • この中でも、Pゲイン(Kp)、Dゲイン(Kd)が重要(敏感)である。Iゲイン(Ki)はあまり効かない。
  • Pゲイン、Dゲインの組み合わせをいろいろ変えてみる。値のオーダー(桁数)は上記程度。
  • PIDパラメータとほぼ平行して調整するのは(4)のPゲインの2乗成分(Ks)である。
  • この値は、スケッチ内で次式のようにモータへの出力パワーを調整している。

    • // 出力を計算する

    Power = Kp * P * (1. + Ks * abs(P)) + Ki * I + Kd * D;

  • すなわち、角度偏差の2乗に比例する成分の感度である。
  • この値で、偏差が大きくなった時のゲインを「非線形」的に(つまり偏差の2乗に比例して)大きくする。
  • Ksはかなり効く。

次に

  • これまでの調整でかなり安定に倒立するはずである．
  • しかし，これらだけでは，「位置が徐々に移動していく」ことは防げない．
  • 理想的には，タイヤの回転から，模型の移動速度や位置をモニターし，出力にフィードバックする必要がある．そのためには，タイヤにエンコーダ等を取付け，回転数等を測らなければならないが，ここでは使わない．
  • そこでここでは、出力パワーが回転数に対応するとして、「疑似的」にフィードバックを掛ける。そのパラメータが(5) 「速度FBゲイン」Kvelと(6) 「位置FBゲイン」Kposである。
  • 「速度FBゲイン」Kvelと「位置FBゲイン」Kposは次式で出力パワーにフィードバックされる。

    • Power = Power + Kpos * pos + Kvel * vel; // 位置のFB

    float Powerlim = constrain(Power, -255., 255.);// 255.に制限されるので

    pos = Kposdec * pos + Powerlim * dt; // 位置

    vel = (pos - prevPos) / dt;

    prevPos = pos;

    // モータのPWM出力

    pwm = constrain(abs((int)Power), V_MIN, V_MAX); // 255に制限する

  • うまく調整できれば，ほぼ同じ位置で倒立する．
  • ただ、このスケッチではKvelは効かない。Kposが重要である。

その他のパラメータ

  • (7) Kpfilt、(8) Kdfiltは、それぞれ、Kp、Kdのローパスフィルタの係数である。
  • 1ループ前の値を使って、急激な変化(ノイズとか)を緩和させる(高周波成分をカットする)役割がある。
  • これらのパラメータは下記の式で使用される。

    • // ローパスフィルタ

    D_filtered = Kdfilt * D_filtered + (1. - Kdfilt) * D_raw;

    D = D_filtered;

    // ローパスフィルタ

    P_filtered = Kpfilt * P_filtered + (1. - Kpfilt) * P_raw;

    P = P_filtered;

  • (9) Kposdecは位置ゲインを減衰させる。そうしないと、どこかで値が飽和する可能性がある。
  • (10) Kpwmaと(11) Kpwmbは、モータA、Bの個体差(ギアの摩擦などを含めた)を保証する．勝手にだんだん左あるいは右回転する場合，調整する．
  • (12) Ktは電池の消耗をある程度補償する。しかし、結局は、動きが鈍くなったら電池を交換した方が良い。
  • パラメータを故意にいろいろ変え，その効果を調べるのも理解を深めることになるので，挑戦して欲しい．

    • これらの調整で、「5分以上」安定に倒立させることができれば、成功である!

  • ただし、BLTのデバイスUUID (Universally Unique Identifier) [他のシステムと重複しない一意な128bit (32桁の16進数)]は、"#"と"$"にしているので、各自設定が必要である。UUIDはサービス用と属性用の二つが必要である。UUIDの取得は、例えば、UUIDGenerator.netなどのオンラインジェネレーターを利用し、バージョン4(ランダム生成)を作成する。
  • このスケッチは、前後移動、左右回転がリモートコントロールが可能である。
  • また、横に倒した状態(倒立していない状態)で、"Kp"、"Ki="、"Kd="、"Ks="、"Kt="をリモートで(USBケーブルを使わす)変更可能である。ただし、転倒すると初期値にもどる(要改善)。また、Arduinoをリセットすると初期値に戻る。

コントロール用WEBパネル

  • BLT-LEでPC上からコントロールするためのWEBパネル(html)の例はindex_スマホ対応_html.txtである。
  • ただし、このhtmlでもBLTのデバイスUUIDを"#"と"$"にしているので、上で取得した二つのUUIDをコピーする。
  • このhtmlをchrome上で動かすには、ChromeでWeb Bluetooth APIを使用することになる。標準で有効だが、一部の環境や古いバージョンでは以下のアドレスをブラウザに入力して設定を確認、変更する必要がある。画面で「Web Bluetoot」をenableにする。変更後、画面右下の[Relaunch]ボタンを押す(再起動)。

    • chrome://flags/#enable-web-bluetooth

  • なお、セキュリティ上の理由から、Web Bluetooth APIは HTTPS (暗号化されたサイト) または localhostでしか動作しない。このhtmlはアンドロイドスマホに対応しているが同様である。htmlをGitHub等で公開して読み込む(GitHubではhttpsで公開される)ことも可能。

コントロール画面

  • 下図のような画面が立ち上がる。
  • まず、「Arduinoに接続」ボタンを押す。接続されると、下部のテキスト領域に表示される。
  • 前後左右のボタンで動きをコントロールする。ボタンを1回押すと少しの間その動作を行う。
  • 動きが大きすぎて、不安定で転倒等する場合は、スケッチの「void bleLoop()」内にある下記部分の、"target_cmd"、"turn_cmd"の値を修正する。

    • // 操作コマンド

    if (cmd == "f") target_cmd += 1.4;

    if (cmd == "b") target_cmd -= 1.4;

    if (cmd == "r"){

    turn_cmd += 60.;

    target_cmd += 0.8; // 少し前進する

    }

    if (cmd == "l"){

    turn_cmd -= 60.;

    target_cmd += 0.8; // 少し前進する

    }

  • "Kp"、"kd"等のパラメータの変更は、「パラメータ調整部」部で例のように入力して、「送信」ボタンを押す。書き換えられたら、下部のテキスト領域に表示される。
  • 途中BLEが途切れたら、Arduinoのリセットボタンを押し、再度接続を試みる。

まとめ

TOPへもどる

  • Arduino等に関して全くの素人であったが、多くの関連サイトやAIに頼って始めた。かなり苦労したが、最終的にはうまく倒立させることができた。
  • 当初最も苦労したのは加速度・ジャイロセンサーへのノイズ対策である。最初はMPU6050をI2C通信で行おうとしていたが、モータを動かさなければ問題無く値を読めたが、モータを動かすと、とたんに不安定になった。コンデンサの追加やGNDの配線路変更など行ったが解決しなかった。そこで、MPU6500に変え、SPI通信に変更したら、即解決した。
  • 次に問題だったのは、傾きに対するモータの応答性である。これは、模型の回転モーメント(重さ、高さ)、回転のトルク(モータのトルク、ギア比、タイヤの大きさ)等が関係し、いろいろ試行錯誤が必要だった。結局、Arduinoとモータの電源に軽量のリチウムポリマー電池を用いる、模型の高さをできるだけ抑えることが効いた。モータ電源の電圧は3.7Vで十分なトルクはあった。
  • Madgwickフィルタの読み出しを200Hzにしたのも、角度の検出速度を上げ、応答性を高めることに効果があった。
  • 制御パラメータの最適化では、PIDパラメータの他、Ks(2乗成分)、Kpos(位置)が効いた。Ksを加えることで、安定度が増した。Kposでフィードバックすることにより、ほぼ一定位置で倒立させることができた。
  • BLEでリモートコントロールを行うと、「ロボット」感覚に近くなる。ぜひ挑戦して欲しい。
  • 最後に、スケッチやコントロールのプログラムなど、AI(ChatGPT、Gemini)に聞くと即座に作成してくれた。この分野では非常に有用なツールであることを改めて感じた。
