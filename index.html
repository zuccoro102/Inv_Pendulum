完成模型

倒立振子モデルとは

TOPへもどる

  • 倒立振子(inverted pendulum)とは、支点よりも重心が高い位置にある振り子をいう。
  • 支点を台車に載せて実装する台車駆動型倒立振子がよく知られている。ほとんどの例において振り子はある回転軸まわりにのみ運動するよう固定されており、自由度は1に制限されている。
  • 振り子は吊り下げられた状態が安定であり、したがって倒立振子は本質的に不安定であるので、倒立状態を保つためには常に能動的に制御する必要がある。このためには支軸に直接トルクを加えたり、支点を水平方向もしくは鉛直方向に移動させることにより振り子の錘の回転速度を変化させたりしてフィードバックループを構築する。支点を動かす型の倒立振子の一番簡単な例は、箒を手の上に立たせる系である。
  • 倒立振子は動力学と制御論における古典的な問題であり、制御システムの学習に適している。
  • 参考：ウィキペディア等。

加速度/ジャイロセンサーの試験

  • 倒立模型では、常にその角度、角速度を検出し、その値からモータを制御する必要がある。(フィードバック)
  • ここでは、6軸の加速度/ジャイロセンサー「MPU6500」を用いて、角度・角速度を測定する。
  • 通信にはSPIを使用する。SPIは、
    • I2C通信に比べて高速通信が可能

TOPへもどる

モータ、ギアボックスの取付け

モータはFA-130型。モータ軸のギアは8歯である。

ノイズ対策として、モータ-端子間、端子-ボディ間には0.1μFのコンデンサをはんだ付けする。電流リード線も同時にはんだ付けする。

モータ固定部品でコンデンサが外れないように注意。しっかりはんだ付けする。

ギアボックスに組み込み(ギア比は114.7:1)、ユニバーサルボードの端に固定する。

ユニバーサルボードの端を少し切り取り、裏側のバー状の部品とねじ止めする。

タイヤは直径55 mmのものを用いる。

Arduino、MPU6500の取付け

Arduinoは、ユニバーサルボート表面のモータギアボックスの隣に、両面テープでしっかり張り付ける。

模型の高さをできるだけ低くしたいので横向き(電源コネクタ、USBコネクタが横にくるように)取り付ける。

ユニバーサルボード裏面のほぼ中央に、両面テープを使ってMPU6500を取り付ける。模型の重心に近い位置が良い。

素子は小型のブレッドボードに差し込み、倒立振子が真っすぐ立った時にセンサーの面がほぼ水平になるように固定する。

表面のArduinoから、裏面のMPU6500に、ユニバーサルボードの穴を通してジャンパー線が配線できるような位置にする。ノイズ対策のため配線はなるべく短くしたい。

L型の部品などを使い、振動してもずれないように両側からしっかり固定する。

DRV8835の取付け、Arduinoとの配線

ユニバーサルボード表面のギアボックスの上に、モータドライバDRV8835を差し込んだ小型のブレッドボードを両面テープで固定する。これも高さを抑えるため。

ArduinoとモータドライバDRV8835を配線する。

電源入力部には、ノイズ対策として470 μFの電解コンデンサを取り付ける。念を入れるなら2個並列に取り付ける。

ArduinoとモータドライバDRV8835を配線する。

Arduinoとモータの配線

モータ2個とDRV8835の配線。後の確認試験で回転が逆だったら赤線と黒線を入れ替えれば良い。

モータ2個とDRV8835を配線する。

ノイズの発生を抑えるため、モータのリード線は捩っている。

MPU6500とArduinoの配線

ArduinoとMPU6500を配線する。

電源入力部には、ノイズ対策として10μFの電解コンデンサと0.1pFのマイカ(セラミック)コンデンサを取り付ける。

ArduinoとMPU6500はユニバーサルボードの表と裏にあるので、ボートの穴をうまく利用する。

ノイズが入らないように、できるだけ短い配線にする。

ノイズ対策として、グラウンドはArduinoから配線する。(スター接続)

電池の取付けとDRV8835との配線

電池は軽量なLiPo電池(3.7V、550mAh)を用いる。

モータ用に、2個の電池を並列に接続するケーブルを製作。コネクタ(JST 2.0 PH 2.0mm)を端に取り付ける(オス)。また、ピン-コネクタ( メス)のジャンパー線を作る。

Arduino用には、2個の電池を直列に接続するケーブルを製作。コネクタを端に取り付ける(オス)。また、DCプラグ(外径5.5mm、内径2.1mm)-コネクタの(メス)ケーブルを作る。

LiPo電池を2個重ねたものを二つ並べ、ユニバーサルボード裏面のMPU6500の下側に取り付ける。

取り付け時にバッテリーを変形させないようにプラ板を保護用に張り付けた方が良い。

モータ用(3.7V、並列)のジャンパー線をモータドライバDRV8835に接続する。

ブレッドボード空いている穴に差し込む。

Arduino用(7.4V、直列)のケーブルは動かす時に電源プラグに接続する。

保護カバーを取り付けよう

転倒してもケーブルやセンサーを壊さないようカバーを取り付けよう。

0.5mm厚アルミ板や、プラ板、カラーボード等できるだけ軽くつくる。両面テープで取り付ける。"前"、"後"が容易に判別できるようにすると便利。

リード線がタイヤに絡まないように適当に固定する。

TOPへもどる

  • いよいよ「倒立」させて行く。
  • Arduino IDEの基本的スケッチ例はArduino_woBLE_ino.txtである。
  • まずは、模型の基本的動作を確認する。USBは接続したままで良い。
    • 電池は充電を完了しておく。モータ用、Arduino用のケーブルのコネクタを接続する。
    • モータ用ジャンパー線をモータドライバに接続する。
    • Arduino用のケーブルを電源プラグに接続する。
    • 最初は寝かせた状態にしておき、プログラムをIDEからArduinoに転送する(書き込む)。プログラムが走り始めるとジャイロのオフセット補正値を自動的に取得する。取得が終わると一瞬モータが回るが、すぐ止まる(倒れているため)。Arduinoのリセットボタンを押すときも同様である。
    • しばらくして、手でほぼ垂直に倒立させ、その位置から前後に傾けたら、車輪が逆方向に動くことを確認する。傾きと回転の方向は下図参照。回転が逆だったら、モータのリード線の配線を変更する。
    • 傾きが大きいほど車輪の回転速度が大きくなることを確認する。
    • さらに傾きを大きくすると(20度以上)、回転が止まることを確認する。もどすと再度回転する。

PID制御とは

TOPへもどる

  • 倒立の調整前にPID制御について知ろう。
  • 参考資料：PID制御とは？メカニズムと役割をわかりやすく解説

オンオフ制御

  • 最も単純な調節動作に、オンオフ動作がある。例えば、バイメタル式の電気こたつ、焼肉等に使う鉄板に採用されている。これらのオンオフ動作では、目標温度まで100%の出力で上昇した後に設定温度を超えると0%になって、温度が下がることで温度調整を行う。しかし、目標温度から戻りすぎや行き過ぎ(オーバーシュート)が発生しやすく、波を打つような制御結果になってしまい、理想的な温度調整にはいたらない。
  • オンオフ制御は、構造が簡単なため安価に構成できる点はメリットだが、上記のような問題がある。

PID制御

  • PID制御とは、温度制御などに用いられる制御方式のことである。目標とする値を設定したあとセンサーで現在の値を読み取って、目標値に近づけようと自動で調整する。PID制御によってオンオフ動作の欠点を解決することができる
  • PIDとは、以下の動作の頭文字を取っている。
    • P動作：Proportional (比例)
    • I動作：Integral (積分)
    • D動作：Derivative (微分)
  • PID制御は、以下の制御式(計算式)とフロー線図によって表される。

PID制御の流れ

  • P動作とは、現在値と設定値の偏差(目標との差)に比例した操作量を比例帯内で働かす動作のこと。オンオフ動作のオーバーシュート(行き過ぎ)やアンダーシュート(戻りすぎ)といった問題を解消することができる。差が大きいほど強く働き、初期の修正を行う。
  • I動作は、P動作と組み合わせてPI動作として用いられる。P動作で生じたオフセット(偏差)を累積させて、その累積値に比例させた量を操作量に加えることで、誤差を補正することが可能となる。過去の偏差を累積し、比例制御だけでは残ってしまう小さな差(オフセット)を解消する。
  • D動作は、外乱の影響などによる急激な変化に反応して出力を修正する。今回の誤差が前回の誤差よりも大きい場合に操作量を変化させることで、急な変動にも対応することができる。 偏差の変化スピードに比例して操作量を調整し、外乱などによる急激な変化に対応し、素早く安定させる。

制御パラメータの調整

TOPへもどる

  • いよいよ「倒立」させて行く。
  • 倒立振子を「安定に」倒立させるためには、振子の傾き等に対して、適切にフィードバックする制御することが必要である。
  • もちろん、振子の傾きに対して、それを復元するに十分な「トルク」を発生させることが必要だが、今回製作したモデルの重さ、大きさ(高さ)、また、使用したモータ、ギア比、電池なら十分なはずである。
  • ただし、長時間動かして電池が消耗した場合はトルクがでなくなるので充電された電池と交換が必要である。1時間程度頻繁に動かすと電池の消耗が目立つようになる。
  • また、ギアにはこまめに潤滑油を塗り、摩耗を防ぐことが大事である。さらに、長時間の運転では、ブラシ式モータではブラシ部の摩耗も起きるので気を付けなければならない。
  • FA-130型モータの定格電圧は3Vである。トルクや回転数を上げようと、あまり大きな電圧を加えないようにする。
  • Arduino UNO R4 wifiの入力電圧は6〜24Vである。電池が消耗し6V以下になると停止する。
  • 以下、スケッチ内の各種パラメータを調整し、安定に倒立させていく。

調整の基本方針

  • 根気強く下記のフローを繰り返す。

    調整の流れ

  • 動作の確認のポイントは倒れ方である。突然倒れる、揺れがだんだん大きくなり倒れていく、一方向に傾きそのまま倒れる、倒れはしないが一方向に動いていく、揺れが大きい、などを見極める。
  • 揺れの様子からどのパラメータを変更すれば良いか推定し(難しいが。。)、調整後また動かしてみる。
  • 基本的に、一回に一つのパラメータを変更するのが「コツ」。

制御パラメータ

  • 制御するパラメータは、スケッチ内の下記パラメータである。値はおおよその値を適当に入れている。

      • // 制御パラメータの初期値

    1. float Kp = 3000.; // Pゲイン
    2. float Ki = 5.0; // Iゲイン
    3. float Kd = 10.0; // Dゲイン
    4. float Ks = 50.0; // Pゲインの2乗
    5. float Kvel = 0.0; // 速度FBゲイン0.1
    6. float Kpos = 0.2; // 位置FBゲイン0.5
    7. float Kpfilt = 0.05; // Pのfilter係数
    8. float Kdfilt = 0.95; // Dのfilter係数
    9. float Kposdec = 0.999; // posの減衰係数
    10. float Kpwma = 1.05; // モータAのPWMの係数、基準は1.0 右側
    11. float Kpwmb = 0.95; // モータBのPWMの係数、基準は1.0 左側
    12. float Kt = 0.7; // 電池の消耗を考慮する係数、最初は~0.7、最後は~1.0、pwmの係数
    13. float target = -6.7; // 目標値 大きくすると前に行く

まずは

  • 最初に調整するのは、調整項目の(13) target、「目標値」(バランスが取れる角度)である。
  • スケッチ書き込みは、模型は倒れている状態で行う。書き込みが終わりプログラムが走りだすとすぐにMPU6500のオフセットの取得が始まる。取得が終わると一瞬タイヤが回転し止まる。その後手で倒立させて、モータがほぼ止まっている角度で手を離し、その直後の動きを確認する。
  • 模型がすぐに一方向にのみ倒れるようであれば、目標値がずれている。target値を調整して、倒れる方向が偏らないような値にする。後で度々微調が必要となるが、まずは粗く調整する。
  • 模型の重さがタイヤに対して対称なら0度近くになるが、電池やモータ等の配置が非対称なので、少し傾いた状態でバランスするはずである。右図の例では-6.7度傾いている。

次は

  • 次に優先して調整するのは、(1)～(3)のPID制御パラメータである。
  • この中でも、Pゲイン(Kp)、Dゲイン(Kd)が重要(敏感)である。Iゲイン(Ki)はあまり効かない。
  • Pゲイン、Dゲインの組み合わせをいろいろ変えてみる。値のオーダー(桁数)は上記程度。
  • PIDパラメータとほぼ平行して調整するのは(4)のPゲインの2乗成分(Ks)である。
  • この値は、スケッチ内で次式のようにモータへの出力パワーを調整している。

    // 出力を計算する

    Power = Kp * P * (1. + Ks * abs(P)) + Ki * I + Kd * D;

  • すなわち、角度偏差の2乗に比例する成分の感度である。
  • この値で、偏差が大きくなった時のゲインを「非線形」的に(つまり偏差の2乗に比例して)大きくする。結構効く。

KpのみKp + Ks

次に

  • これまでの調整でかなり安定に倒立するはずである。
  • しかし、これらだけでは、「位置が徐々に移動していく」ことは防げない。
  • 理想的には、タイヤの回転から、模型の移動速度や位置をモニターし、出力にフィードバックする必要がある。そのためには、タイヤにエンコーダ等を取付け、回転数等を測らなければならないが、ここでは使わない。
  • そこで、出力パワーが回転数に対応するとして、「疑似的」にフィードバックを掛ける。そのパラメータが(5) 「速度FBゲイン」Kvelと(6) 「位置FBゲイン」Kposである。
  • 「速度FBゲイン」Kvelと「位置FBゲイン」Kposは次式で出力パワーにフィードバックされる。

    Power = Power + Kpos * pos + Kvel * vel; // 位置のFB

    float Powerlim = constrain(Power, -255., 255.);// 255.に制限されるので

    pos = Kposdec * pos + Powerlim * dt; // 位置

    vel = (pos - prevPos) / dt;

    prevPos = pos;

    // モータのPWM出力

    pwm = constrain(abs((int)Power), V_MIN, V_MAX); // 255に制限する

  • うまく調整できれば、ほぼ同じ位置で倒立する。
  • ただ、このスケッチではKvelはほとんど効かなかった。Kposが重要である。

その他のパラメータ

  • (7) Kpfilt、(8) Kdfiltは、それぞれ、Kp、Kdのローパスフィルタの係数である。
    • 1ループ前の値を使って、急激な変化(ノイズとか)を緩和させる(高周波成分をカットする)役割がある。
    • これらのパラメータは下記の式で使用される。

    // ローパスフィルタ

    D_filtered = Kdfilt * D_filtered + (1. - Kdfilt) * D_raw;

    D = D_filtered;

    // ローパスフィルタ

    P_filtered = Kpfilt * P_filtered + (1. - Kpfilt) * P_raw;

    P = P_filtered;

  • (9) Kposdecは位置ゲインを減衰させる。そうしないと、どこかで値が飽和する可能性がある。
  • (10) Kpwmaと(11) Kpwmbは、左右のモータA、Bの個体差(ギアの摩擦などを含めた)を保証する。勝手にだんだん左あるいは右に回転する場合、調整する。
  • (12) Ktは電池の消耗をある程度補償する。しかし、結局は、動きが鈍くなったら電池を交換した方が良い。
  • パラメータを故意にいろいろ変え、その効果を調べるのも理解を深めることになるので、挑戦して欲しい。

    • これらの調整で、「5分以上」安定に倒立させることができれば、成功です!

Bluetoothによるコントロール

TOPへもどる

  • Arduino Uno R4 WifiではBluetoot Low Energy (BLT-LE)で通信が可能である。
  • 安定に倒立させることができたら、Bluetoothによるリモートコントロールに挑戦してみよう。

スケッチ例

  • IDEのスケッチ例はArduino_wBLE_ino.txt である。
  • ライブラリのインストール: Arduino IDEのライブラリマネージャーで「ArduinoBLE」を検索し、インストールする。
  • ただし、BLTのデバイスUUID (Universally Unique Identifier) [他のシステムと重複しない一意な128bit (32桁の16進数)]は、"#"と"$"にしているので、各自設定が必要である。UUIDはサービス用と属性用の二つが必要である。UUIDの取得は、例えば、UUIDGenerator.netなどのオンラインジェネレーターを利用し、バージョン4(ランダム生成)を作成する。
  • このスケッチでは、前後移動、左右回転がリモートコントロールが可能である。
  • また、横に倒した状態(止まっている状態)で、"Kp"、"Ki"、"Kd"、"Ks"、"Kt"をリモートで(USBケーブルを使わす)変更可能である。なお、Arduinoをリセットすると初期値に戻る。

コントロール用WEBパネル

  • BLT-LEでPC上からコントロールするためのWEBパネル(html)の例はControl_smart_html.txtである。
  • ただし、このhtmlでもBLTのデバイスUUIDを"#"と"$"にしているので、上で取得した二つのUUIDをコピーする。
  • このhtmlをchrome上で動かすには、ChromeでWeb Bluetooth APIを使用することになる。このAPIは標準で有効だが、一部の環境や古いバージョンでは以下のアドレスをブラウザに入力して設定を確認、変更する必要がある。画面で「Web Bluetoot」をenableにする。変更後、画面右下の[Relaunch]ボタンを押す(再起動)。

    chrome://flags/#enable-web-bluetooth

  • なお、セキュリティ上の理由から、Web Bluetooth APIは HTTPS (暗号化されたサイト) または localhostでしか動作しない。このhtmlはアンドロイドスマホに対応しているが同様である。htmlをGitHub等で公開して読み込む(GitHubではhttpsで公開される)ことも可能。

コントロール画面

  • chromeで開くと下図のような画面が立ち上がる。
  • まず、「Arduinoに接続」ボタンを押してペアリングする。接続されると、下部のテキスト領域にその旨表示される。
  • 前後左右のボタンで動きをコントロールする。ボタンを1回押すと少しの間その動作を行う。
  • 動きが大きすぎて、不安定で転倒等する場合は、スケッチの「void bleLoop()」内にある下記部分の、"target_cmd"、"turn_cmd"の値を修正する。

    // 操作コマンド

    if (cmd == "f") target_cmd += 1.4;

    if (cmd == "b") target_cmd -= 1.4;

    if (cmd == "r"){

    turn_cmd += 60.;

    target_cmd += 0.8; // 少し前進する

    }

    if (cmd == "l"){

    turn_cmd -= 60.;

    target_cmd += 0.8; // 少し前進する

    }

  • "Kp"、"kd"等のパラメータの変更は、倒れている時に「パラメータ調整部」部で例のように入力して、「送信」ボタンを押す。書き換えられたら、下部のテキスト領域に表示される。
  • 途中BLEが途切れたら、Arduinoのリセットボタンを押し、再度接続を試みる。ただし、リセットするとパラメータは初期値に戻るので注意。

まとめ

TOPへもどる

  • Arduino等に関して全くの素人であったが、多くの関連サイトやAIに頼って始めた。かなり苦労したものの、最終的にはうまく倒立させることができた。
  • 当初最も苦労したのは加速度・ジャイロセンサーへのノイズ対策である。最初はMPU6050をI2C通信で行おうとしていた。モータを動かさなければ問題無く値を読めたが、モータを動かすと、とたんに不安定になった。コンデンサの追加やGNDの配線路変更など行ったが解決しなかった。そこで、MPU6500に変え、SPI通信に変更したら、即解決した。
  • 次に問題だったのは、傾きに対するモータの応答性である。これは、模型の回転モーメント(重さ、高さ)、回転のトルク(モータのトルク、ギア比、タイヤの大きさ)等が関係し、いろいろ試行錯誤が必要だった。結局、Arduinoとモータの電源に軽量のリチウムポリマー電池を用いる、模型の高さをできるだけ抑えることが効いた。モータ電源の電圧は3.7Vで十分なトルクがあった。
  • Madgwickフィルタへの角速度の入力パラメータの単位がdegree/sであることに注意が必要である。Madgwickフィルタの読み出しを200Hzにしたのも、角度等の検出速度を上げ、応答性を高めることに効果があった。
  • 制御パラメータの最適化では、PIDパラメータの他、Ks(2乗成分)、Kpos(位置)が効いた。Ksを加えることで、安定度が増した。Kposでフィードバックすることにより、ほぼ一定位置で倒立させることができた。
  • BLEでリモートコントロールを行うと、「ロボット」感覚に近くなる。ぜひ挑戦して欲しい。
  • 最後に、スケッチやコントロールのプログラムなど、AI(ChatGPT、Gemini)に聞くと即座に(ほぼ問題無く)作成してくれた。この分野ではAIが非常に有用なツールであることを改めて感じた。
